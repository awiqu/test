# RC-8 — 8-битный компьютер на редстоуне для Minecraft 26.2

Готовый к постройке компьютер: 8 регистров, 16-битные команды, ПЗУ на 512 команд, 16 инструкций,
8-битное АЛУ, дисплей 32×32 на медных фонарях, три 8-сегментные цифры, пульт управления
(Start / Stop / Step / Reset, рычаг скорости, 4 рычага ввода), секвенсор-«часы» с замеренным временем команды.
Всё сгенерировано кодом из этого репозитория, проверено на реальном сервере Minecraft 26.2 и
сверено с эмулятором на Python.

| Что | Как реализовано |
|---|---|
| Регистры | 8 × 8 бит, защёлки на повторителях с блокировкой, чтение компаратором-вычитателем |
| Команды | 16 бит, 16 инструкций (таблица ниже) |
| ПЗУ | 512 × 16 бит, 4 банка (факельные ПЛМ); программа = факелы в B-плоскости, меняется датапаком |
| АЛУ | 8 бит: ADD/SUB/ADC/AND/OR/XOR/SHR, флаги Z и C, последовательный перенос |
| Дисплей | 32 × 32, `PLOT x,y` переключает (XOR) пиксель — медный фонарь (T-триггер) |
| Цифры | 3 × (7 сегментов + точка) на лампах, `OUT Dn,Rm` пишет hex-цифру |
| Ввод | 4 рычага (`IN`), кнопки Start/Stop/Step/Reset, рычаг SLOW |
| Такт | самосинхронное кольцо импульсов p1→p2→p3, длительности настраиваются (см. «Время команды») |

## Что лежит в репозитории

```
dist/                     готовая постройка (после tools/build.py)
  datapack/rc8            датапак: /function rc8:prepare, rc8:build
  datapack/rc8_rom        прошивка ПЗУ (test_all): /function rc8_rom:load
  roms/<программа>/rc8_rom   прошивки других примеров (stress, demo_count, fuzz7) — подменяют datapack/rc8_rom
  rc8.nbt  rc8.schem  rc8.litematic   та же постройка целиком (структура, WorldEdit, Litematica)
programs/                 примеры на ассемблере RC-8
tools/rc8asm.py           ассемблер / дизассемблер / эмулятор
tools/build.py            полная сборка (ассемблер → ПЗУ → размещение → трассировка → экспорт)
tools/romgen.py           «генератор схематик ПЗУ»: программа → факелы B-плоскости → датапак
tools/run_sys.py          прогон постройки на живом сервере и сверка с эмулятором
redcomp/                  библиотека: ячейки, ПЛМ, размещение, трассировщик, экспорт, эмулятор
```

## Быстрый старт (готовый датапак)

1. Плоская местность (superflat идеален), свободное место примерно **920 × 880 блоков** (≈ 58 × 55 чанков)
   в сторону +X (восток) и +Z (юг) от точки, где вы стоите. Постройка начинается у вас под ногами:
   дорожки лежат на уровне ваших ног, «плата» (серый бетон) — на блок ниже.
2. Скопируйте `dist/datapack/rc8` и `dist/datapack/rc8_rom` в `<мир>/datapacks/`, выполните `/reload`
   (или создайте мир с этими датапаками).
3. Встаньте в северо-западный угол площадки и выполните по очереди:
   ```
   /function rc8:prepare     # принудительная загрузка чанков + плата
   /function rc8:build       # ставит постройку, обновляет блоки и сам делает автосброс (≈ 5 минут игрового времени)
   ```
   Игрок должен оставаться в игре и **чанки должны быть загружены** (prepare делает `forceload`), иначе
   редстоун в незагруженных чанках не работает. Функция `rc8:unload` снимает принудительную загрузку.
4. Через ~5 минут игрового времени (≈ 6000 тиков) машина сама дважды «нажмёт» RESET и остановится (лампа RUN погаснет).
   Пульт — у южного края дисплея.

Если у вас нет датапаков: `dist/rc8.schem` (WorldEdit: `//schem load rc8`, `//paste`) или `dist/rc8.litematic`
(Litematica). После вставки схематикой обязательно «встряхните» постройку (см. ниже «Особенности»).

## Пульт управления

| Орган | Действие |
|---|---|
| **START** (кнопка) | запускает программу с текущего адреса |
| **STOP** | останавливает после завершения текущей команды |
| **STEP** | выполняет ровно одну команду |
| **RESET** | сбрасывает PC в 0 (нажимать при остановленной машине) |
| рычаг **SLOW** | включён — такт медленнее (добавлена цепочка задержки), удобно смотреть исполнение |
| рычаги **IN0…IN3** | читаются командой `IN Rd` (биты 0..3) |
| лампа **RUN** | горит, пока машина работает; гаснет после `HLT` или STOP |

Команда `HLT` останавливает машину. После постройки автосброс выполняется сам; если вы сменили программу
(`rc8_rom:load`), нажмите RESET.

## Набор команд

Слово 16 бит: `[15:12]` код операции, `[11:9]` rd, `[8:6]` ra, `[5:3]` rb; `LDI`: `imm8` в `[7:0]`; `ADDI`: `imm6` (знаковое)
в `[5:0]`; `JMP`: адрес `[8:0]`; `Jcc`: условие в `[11:9]`, адрес `[8:0]`.

| Код | Команда | Действие |
|---|---|---|
| 0 | `NOP` / `HLT` | ничего / остановка |
| 1 | `LDI rd, imm8` | rd = imm8 |
| 2 | `ADD rd, ra, rb` | rd = ra + rb; Z, C |
| 3 | `SUB rd, ra, rb` | rd = ra − rb; C = нет заёма |
| 4 | `AND` · 5 `OR` · 6 `XOR` | побитово; Z (C = 0) |
| 7 | `SHR rd, ra` | rd = ra >> 1; C = выдвинутый бит |
| 8 | `ADC rd, ra, rb` | rd = ra + rb + C |
| 9 | `ADDI rd, ra, imm6` | rd = ra + imm6 |
| 10 | `CMP ra, rb` | флаги по ra − rb |
| 11 | `JMP addr` | безусловный переход |
| 12 | `JZ / JNZ / JC / JNC addr` | условные переходы |
| 13 | `IN rd` | rd = рычаги (4 бита) |
| 14 | `OUT Dn, ra` | цифра n (0..2) = hex(ra[3:0]), точка = ra[7] |
| 15 | `PLOT ra, rb` | переключить пиксель x = ra[4:0], y = rb[4:0] |

Псевдокоманды: `MOV, INC, DEC, CLR, SHL`. Директивы: метки `name:`, `.org N`, `.word N`.

```
python3 tools/rc8asm.py programs/test_all.asm            # листинг
python3 tools/rc8asm.py programs/test_all.asm --run      # эмулятор: регистры, цифры, дисплей
python3 tools/rc8asm.py --dis 125a                       # дизассемблер слова
```

## Загрузка программы в ПЗУ («генератор схематик»)

Программа записывается факелами в B-плоскости четырёх банков ПЗУ. Генератор делает по структуре на банк
(факел там, где бит = 1, воздух там, где 0) и функцию-загрузчик:

```
python3 tools/romgen.py my.asm --meta dist/work/rc8_meta.pkl --out dist/datapack
# в игре, стоя в той же точке, что и при rc8:build:
/reload
/function rc8_rom:load
```
После загрузки нажмите RESET, затем START. (Заменить программу можно в любой момент — машина должна быть остановлена.)
Не бочки с предметами, а факельная матрица: она плотнее и не требует декодирования силы сигнала.

## Время команды и такт

Секвенсор — кольцо повторителей, по которому бегает один импульс. На его отводах берутся три фазы:

* **p1** — защёлкнуть результат АЛУ, флаги и следующий адрес;
* **p2** — запись в регистр / цифра / пиксель / HLT;
* **p3** — переключить счётчик команд (запускает чтение следующей команды из ПЗУ).

Длительности — это настраиваемые задержки повторителей (`tools/retime.py`). Критический путь измерен на готовой
постройке (p3 → PC → ПЗУ → управление → регистры → АЛУ → результат: PC меняется через ≈ 240, команда на шине через ≈ 410,
результат АЛУ установился через 670…1030 тиков после p3 в зависимости от команды):

| Фаза цикла | Задержка (игровых тиков) | Что обеспечивает |
|---|---|---|
| p3 → p1 (`d4` + `d1` + кольцо) | ≈ 1180 | установление: ПЗУ → управление → регистры → АЛУ (замер худшего случая — `ADD 0xFF+1`, перенос через все разряды: ≈ **1030** от p3) |
| p1 → p2 (`d2`) | 120 | защёлка результата, подвод к регистрам |
| p2 → p3 (`d3`) | 80 | запись завершена до смены адреса |
| ширина импульса (`dw`) | ≈ 50 + проводка | |
| **итого, период команды** | **1320 тиков ≈ 66 с** при 20 TPS | рычаг SLOW добавляет 480 → 1800 тиков ≈ 90 с |

Запас по установлению ≈ 15 % (выбран по замерам: период 840 тиков уже давал сбои в цепочке `ADC 0xFF+0xFF+1`, 960 проходил,
1320 — рабочее значение). Задержки задаются без повторной трассировки: `python3 tools/retime.py dist/work dw=50,d1=560,d2=120,d3=80,d4=560,dx=480`
(затем перегенерировать датапак). На практике: команда ≈ минута реального времени при штатных 20 TPS; в тестовом сервере
со `/tick rate 10000` (максимум, что тянет сервер) полный `test_all` (26 команд) выполняется за ≈ 3 минуты, `stress` (18 команд) — ≈ 2 минуты.

Ускорить: `/tick rate 100` (5×) и т. д. — схема детерминирована по игровым тикам и от скорости их течения не зависит.

## Проверка

* Каждый модуль проверялся на живом сервере отдельно (ПЛМ, регистры, АЛУ-срез против нетлиста, ПЗУ, пиксель, цифра, секвенсор).
* Полная постройка прогоняется `tools/run_sys.py` и сверяется с эмулятором: регистры, цифры, пиксели.
  Программы: `programs/test_all.asm` (арифметика/логика/флаги/цикл/цифры/дисплей/IN), `programs/stress.asm`
  (цепочки переноса, ADC, переходы через все адреса ПЗУ, замена ПЗУ датапаком) и случайная `programs/fuzz7.asm`
  (56 команд, рычаги 1010, `tools/fuzz.py`) — регистры, цифры и пиксели совпали с эмулятором.
  Рычаг SLOW проверен отдельно: программа даёт тот же результат, но идёт медленнее.
* Offline-проверки в сборке: все цепи достижимы и без замыканий (`redcomp/netcheck.py`).

## Особенности и честные оговорки

* **Размер.** Это не компактный «кубик»: площадка ≈ 917 × 877 блоков, ≈ 361 тыс. блоков (212 тыс. пыли, 22 тыс. повторителей,
  7,7 тыс. настенных факелов, 1,2 тыс. компараторов, 1024 медных фонаря). Модули (ПЗУ, регистры, АЛУ, дисплей и т. д.)
  раскрашены бетоном по функциям и подписаны табличками; проводка — на сером бетоне. Мощный сервер и `forceload` обязательны.
* **Компоненты «из интернета» не использовались** — доступа к ним не было; все модули (ПЛМ, регистровый файл, АЛУ,
  ПЗУ, секвенсор, дисплей) сгенерированы кодом и верифицированы на сервере.
* **Дисплей — XOR**: `PLOT` переключает пиксель. Очистить дисплей: `/function rc8:clear_display`.
  Фонари «вощёные», не окисляются.
* **Старт после постройки.** Защёлки в момент постановки блоков находятся в случайных состояниях; функция
  `rc8:build` сама делает «встряску» обновлений и дважды нажимает RESET. При вставке схематикой/структурой вручную
  выполните `/function rc8:refresh` пару раз и дважды нажмите RESET.
* **Структура одним куском.** Плитками ставить нельзя: на границах плиток `place template` ломает настенные факелы,
  опора которых лежит в соседней плитке (поэтому `build` использует один большой шаблон).
* **Нагрузка.** При смене команды обновляются тысячи блоков; сервер легко упирается в один поток (при 20 TPS остаётся запас,
  но при очень большом `/tick rate` будет тормозить — это не ломает логику, схема считается в игровых тиках).
* **Цифры не сбрасываются RESET'ом** (хранят последнее значение); дисплей очищается `/function rc8:clear_display`.

## Пересборка

```
python3 tools/build.py programs/test_all.asm --out dist     # ≈ 10–40 минут (размещение + трассировка)
```
Нужен `g++` (трассировщик на C++: `redcomp/cpp/pf.cpp` → `build/pf`; перед первым запуском:
`g++ -O2 -std=c++17 -o build/pf redcomp/cpp/pf.cpp`). Для проверок на сервере нужны JDK 25 и сервер 26.2 с включённым RCON
(`tools/rcon.py`).
