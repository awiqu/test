# Устройство RC-8

## Поток данных

```
 PCL (счётчик команд, 9 бит) ──► ПЗУ 512×16 ──► IR (16 линий)
                                                   │
        ┌──────────────┬──────────────┬────────────┼─────────────┬───────────────┐
   УПРАВЛЕНИЕ      выбор Ra/Rb     КОНСТАНТА     ПЕРЕХОДЫ     дешифр. записи   адрес JMP
   (ПЛМ: sub,fS,…)    (ПЛМ 3→8)       (ПЛМ)       (ПЛМ)         (ПЛМ 3→8)          │
        │                 │              │            │              │              │
        │            регистры A / B      │            │              │              │
        │            (R0..R7, 2 копии)   │            │              │              │
        │                 └──► АЛУ 8 бит (8 одинаковых срезов) ◄─────┘              │
        │                          │                                                 │
        │                    RES (защёлка) ──► запись в регистры                    │
        │                          └──► флаги Z, C (защёлка FLG) ──► условия        │
        └──────────────────────────────────────────────────────► PC-логика: pc+1 / jump / reset ─► NPC ─► PCL
```

Порядок в одном цикле (такт — кольцо импульсов в секвенсоре):

1. После `p3` PCL получает новый адрес, ПЗУ выдаёт слово, декодеры и АЛУ вычисляют результат (установление ≈ 600 тиков);
2. `p1` — защёлкнуть результат в RES, флаги в FLG, следующий адрес в NPC;
3. `p2` — запись RES в регистр `rd` (или в цифру `OUT`, или переключение пикселя `PLOT`, или `HLT`);
4. `p3` — PCL := NPC.

Все декодеры, включая ПЗУ, — двухплоскостные факельные ПЛМ (NAND-плоскость → OR-плоскость); защёлки — повторитель-D с блокировкой;
регистры читаются компаратором в режиме вычитания (AND-NOT) и пишутся через блокированный повторитель.

## Модули (`redcomp/system.py`)

| Модуль | Цвет бетона | Что это |
|---|---|---|
| control, selA, selB, wrdec, imm, jump, pulse, flags, digsel | жёлтый | ПЛМ управления |
| pc, NPC, PCL | оранжевый | счётчик команд |
| regA, regB | зелёный | регистровый файл (две копии, чтобы читать два операнда) |
| alu, RES, FLG | красный | 8 срезов АЛУ (автоматически разведены решёточным размещением/трассировкой), результат, флаги |
| rom | голубой | 4 банка × 128 слов; A-плоскость фиксирована, программа — факелы B-плоскости |
| seq | фиолетовый | секвенсор: RUN/RESET-защёлки, моностабильный генератор, цепочки задержек p1–p3 |
| hex7, DIG0..2, dgt0..2 | голубой/пурпурный/чёрный | декодер hex→7 сегментов, защёлки цифр, сами цифры |
| coldec, rowdec, pixels | бирюзовый/чёрный | декодеры X/Y и матрица 32×32 |
| panel | белый | кнопки, рычаги, лампа RUN |

Проводка между модулями проложена глобальным трассировщиком (PathFinder на решётке 2×2, два слоя, рампы), серый бетон.

## Как это проверялось

* `redcomp/isa.py` — эталонный эмулятор. Его результаты сравниваются с постройкой в мире (`tools/run_sys.py`).
* Для каждого типа ячейки есть тест на живом сервере (в историю коммитов вошли `tools/*lab*.py`).
* `redcomp/netcheck.py` — моделирует правила соединения пыли Minecraft и проверяет, что каждая цепь достижима, а уровни сигналов у приёмников ≥ 13; ищет замыкания между цепями.

## Подводные камни Minecraft, которые пришлось учесть (и которые зашиты в генераторы)

* `facing` повторителя/компаратора — сторона ВХОДА; сторонний вход компаратора-вычитателя должен быть ровно 15 → перед ним стоит регенератор.
* Пыль на рампе не соединяется с пином, над которым стоит блок → пины подключаются только плоско, с повторителем у пина.
* Входы срезов АЛУ рассчитаны на уровень 15 → «слабые» выходы (АЛУ, регистры) получают повторитель сразу у источника.
* Настенные факелы на границах `place template` гибнут (`updateShapeAtEdge`) → одна общая структура.
* Старт: после постановки блоков часть факелов «перегорает»/защёлки в случайном состоянии → несколько проходов `/clone` на месте и автосброс.
* Медные фонари окисляются → «вощёные».
