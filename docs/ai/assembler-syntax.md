# Синтаксис ассемблера RedLogic

Ассемблер один и тот же во встроенной версии (в браузере) и в сгенерированном Python-файле `assembler.py` — результат побитово совпадает.
Мнемоники и формат операндов берутся из набора инструкций **вашего** процессора (`instructions[].mnemonic` и `format`).

## Строка программы

```
[метка:] [мнемоника операнд, операнд, …] [; комментарий]
```

* Комментарии: `;` или `//` до конца строки.
* Метки: `имя:` — адрес следующей инструкции/данных. На одной строке может быть несколько меток; метка может стоять отдельно.
* Мнемоники и имена регистров не зависят от регистра (`ADD` = `add`); имена меток — тоже (настройка `caseSensitiveLabels`).
* Операнды разделяются запятыми, порядок = порядок полей в `format` инструкции.

## Операнды по типам полей

| Поле | Как писать | Пример |
|---|---|---|
| `rd`, `rs`, `rt` | регистр `r0`, `r1`, … (префикс настраивается; по умолчанию `r`) | `add r1, r2` |
| `imm` | выражение: число, символ, метка/константа; допустимо `#` перед числом | `ldi r0, 'A'`, `ldi r1, #0x10` |
| `addr` | выражение — адрес в памяти данных; имена портов (`LEDS`, `TXT`, …) — это адреса; скобки `[ ]` допустимы | `st LEDS, r0`, `ld r1, [10]` |
| `target` | выражение — адрес в ПЗУ (обычно метка) | `jnz loop` |
| `off` | абсолютный адрес (метка); ассемблер сам вычисляет смещение от текущего адреса | `bne loop` |

`imm` может быть отрицательным (`-1`), если число помещается в `dataBits` бит со знаком (−2^(n−1) … 2^n − 1); хранится как дополнительный код.

## Выражения

Числа `42`, `0x2A`, `0b101010`; символы `'A'`, `'\n'`; `$` — адрес текущей строки; метки и константы; операции `+ - * / % << >> & | ^ ~` и скобки.

## Директивы

| Директива | Действие |
|---|---|
| `.org адрес` | продолжить ассемблирование с указанного адреса ПЗУ |
| `.equ ИМЯ, значение` или `ИМЯ = значение` | именованная константа |
| `.word v1, v2, …` | записать слова прямо в ПЗУ |
| `.fill n[, значение]` | `n` слов (по умолчанию 0) |
| `.string "текст"` | символы + завершающий 0 в ПЗУ (`.ascii` — без нуля); экранирование `\n \t \r \0 \\ \"` |

⚠ **Данные в `.word`/`.string` лежат в ПЗУ** (память команд). Гарвардский процессор не может прочитать ПЗУ обычной командой чтения памяти, поэтому
для вывода текста пишите символы в порт командами (`ldi r0, 'H'` / `st TXT, r0`) или заранее раскладывайте константы в ОЗУ.

## Встроенные константы

* имена портов устройств: `LEDS`, `SWITCH`, `BTN`, `SEG`, `TXT`, `TXTPOS`, `PX`, `PY`, `PIX`, `PCLR`, `KEY`, `TIMER`, `RAND`, `SOUND`, `TERM` — только те, что есть в вашем процессоре;
* `ROM_SIZE`, `RAM_SIZE`, `STACK_TOP` (если включён стек).

## Пример (регистровая машина)

```asm
; считаем от 1 до 5 и выводим в светодиоды
        ldi  r0, 0
        ldi  r1, 1
        ldi  r2, 5
loop:   add  r0, r1
        st   LEDS, r0
        cmp  r0, r2
        jnz  loop
        hlt
```

## Пример (аккумулятор)

```asm
        ldi 1
        sta 0
        ldi 0
        sta 1
loop:   lda 1
        add 0
        sta 1
        sta LEDS
        jmp loop
```

## Типичные ошибки

| Сообщение | Причина |
|---|---|
| `Неизвестная инструкция «MOVE»` | такой мнемоники нет в наборе вашего процессора — используйте только перечисленные |
| `ADD ждёт операндов: 2 (rd, rs), получено 3` | неверное число операндов |
| `ожидался регистр r0…r3` | в этом процессоре регистров меньше |
| `значение 300 не помещается в 8 бит` | константа шире слова данных |
| `переход на N слишком далёк` | для `off`: переход дальше, чем позволяет `pcBits` |
| `Программа не помещается в ПЗУ` | слишком много слов — сократите программу |
| `Неизвестное имя «foo»` | метка/константа не определена |

## Советы для программ в ПЗУ-бочках

* ПЗУ маленькое (обычно 16–256 слов): избегайте раскрутки циклов, используйте подпрограммы (если есть `CALL`/`RET`).
* Не оставляйте «дыры» через `.org` без необходимости — каждое слово это 2–8 бочек.
* Программа должна заканчиваться `HLT` или бесконечным циклом — иначе `PC` убежит в пустую память (нулевое слово обычно `NOP`).
