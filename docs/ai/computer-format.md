# Формат описания компьютера (`redlogic-computer`)

Весь компьютер — один JSON: **характеристики** (`spec`), **набор инструкций** (`instructions`) и, по желанию, **программы** (`programs`).
Импорт: «Компьютеры → ИИ и документация → Вставить JSON». Все ошибки приложение выводит списком — его можно целиком отправить обратно модели.

## Модель машины

* **Гарвардская архитектура.** ПЗУ (программа) и данные — разные пространства.
  * ПЗУ: `romWords` слов по `instrBits` бит; адресуется счётчиком команд `PC` (`pcBits` бит). Читается только процессором при выборке команд.
  * Данные: адреса `0 … 2^ramAddrBits − 1`. Нижняя часть — ОЗУ (`ramWords` слов по `dataBits` бит), **верхняя часть — порты устройств** (карта строится автоматически, устройства идут по порядку в `spec.devices`, порты внутри устройства — по порядку).
* Каждая инструкция — **одно слово ПЗУ**. Слово: `opcodeBits` старших бит — код операции, дальше подряд поля операндов в том порядке, как они перечислены в `format`; свободные младшие биты не используются (нули).
* Ширина полей: `rd`, `rs`, `rt` — по `ceil(log2(regCount))` бит; `imm` — `dataBits`; `addr` — `ramAddrBits`; `target` и `off` — `pcBits` (`off` — знаковое смещение от адреса самой инструкции).
* Условие: `opcodeBits + сумма ширин полей ≤ instrBits`, иначе инструкция не помещается.
* После выполнения инструкции `PC` увеличивается на 1, если инструкция сама не записала `PC`.
* Стек (если включён): растёт вниз; `SP` в начале = `ramWords`; занимает верхние `stack.words` слов ОЗУ.
* Архитектуры: `register` (регистры `R[0..regCount-1]`, операнды `rd/rs/rt`) и `accumulator` (один регистр — аккумулятор `A`, полей `rd/rs/rt` нет).

## Корень файла

```jsonc
{
  "format": "redlogic-computer",     // обязательно
  "spec": { … },                     // характеристики
  "instructions": [ … ],             // набор инструкций
  "programs": [ { "name": "…", "source": "…ассемблер…" } ]   // необязательно
}
```

## `spec`

| Поле | Тип / диапазон | По умолчанию | Смысл |
|---|---|---|---|
| `name` | строка | «Компьютер» | название |
| `arch` | `"register"` \| `"accumulator"` | `register` | архитектура |
| `dataBits` | 2…16 | 8 | разрядность данных |
| `regCount` | степень двойки 2…16 (для accumulator всегда 1) | 4 | число регистров |
| `instrBits` | 8…32 | 16 | ширина слова ПЗУ |
| `opcodeBits` | 1…`instrBits−1` | 5 | бит кода операции (кодов будет `2^opcodeBits`) |
| `pcBits` | 1…12 | 6 | бит адреса ПЗУ |
| `romWords` | 1…`2^pcBits` | `2^pcBits` | сколько слов ПЗУ |
| `ramAddrBits` | 1…12 | 8 | бит адреса данных |
| `ramWords` | 0…(`2^ramAddrBits` − число портов) | 128 | размер ОЗУ |
| `flags` | подмножество `["Z","C","N","V"]` | `["Z","C","N"]` | какие флаги есть |
| `aluOps` | подмножество списка ниже | 10 базовых | какие операции умеет АЛУ |
| `stack` | `{ "enabled": bool, "words": 2…ramWords }` | выключен | стек в ОЗУ |
| `clockTicks` | 1…64 | 4 | тиков редстоуна на такт (для оценки скорости) |
| `devices` | массив устройств | `[]` | периферия |

**Флаги.** `Z` — результат 0. `C` — перенос при сложении, **заём при вычитании** (`a < b`), выдвинутый бит при сдвигах. `N` — старший бит результата. `V` — знаковое переполнение.

**АЛУ (`aluOps`)**: `ADD SUB AND OR XOR NOT SHL SHR ASR ROL ROR INC DEC NEG MUL`.
В RTL разрешены только функции выбранных операций (`add`, `sub`, … — см. [rtl-reference.md](rtl-reference.md)).

### Устройства (`spec.devices[]`)

Можно писать полным объектом `{ "type": "leds", "options": { "count": 8 } }` или коротко строкой `"leds"` (параметры по умолчанию).

| `type` | Параметры (`options`) | Порты (имя → доступ) |
|---|---|---|
| `leds` | `count` (8) | `LEDS` rw — биты → лампы |
| `switches` | `count` (8) | `SWITCH` r — рычаги |
| `buttons` | `count` (4) | `BTN` r — кнопки |
| `sevenseg` | — | `SEG` rw — число (hex-цифры) |
| `text` | `cols` (16), `rows` (2) | `TXT` w — символ (10 перевод строки, 12 очистка, 8 забой, 13 в начало строки); `TXTPOS` rw — позиция курсора |
| `pixel` | `width` (8), `height` (8) | `PX` rw, `PY` rw — координаты; `PIX` rw — бит 0 = пиксель; `PCLR` w — очистка |
| `keyboard` | — | `KEY` rw — код нажатой клавиши (0 — нет), чтение сбрасывает |
| `timer` | `period` (16) | `TIMER` rw — счётчик растёт раз в `period` тактов |
| `random` | — | `RAND` r — случайное число |
| `sound` | — | `SOUND` w — нота 0…24 |
| `terminal` | — | `TERM` w — ASCII-символ в журнал |

Имена портов можно использовать как константы-адреса и в ассемблере, и в RTL (`LEDS`, `TXT`, …). Всего портов `P` ⇒ порты занимают адреса `2^ramAddrBits − P … 2^ramAddrBits − 1`.

## `instructions[]`

```json
{
  "mnemonic": "ADD",
  "opcode": 5,
  "format": "rd,rs",
  "description": "Сложение регистров",
  "pseudo": "rd ← rd + rs; обновить флаги",
  "code": "R[rd] = add(R[rd], R[rs])",
  "cycles": 1
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `mnemonic` | да | латинские буквы/цифры, начинается с буквы, регистр не важен; уникальна |
| `opcode` | да | целое `0 … 2^opcodeBits − 1`, уникально (можно строкой `"0x05"`) |
| `format` | нет (`""`) | список полей через запятую: `rd`, `rs`, `rt`, `imm`, `addr`, `target`, `off`; порядок = порядок операндов в ассемблере и в слове; поля не повторяются |
| `description` | нет | человекочитаемое описание |
| `pseudo` | нет | псевдокод для человека |
| `code` | да | исполняемое описание на языке **RTL** ([rtl-reference.md](rtl-reference.md)). Именно оно исполняется в симуляторе |
| `cycles` | нет (1) | число тактов |

Поля из `format` доступны в `code` как переменные с теми же именами (`imm`, `addr`, `target`, `off` — числа; `rd`, `rs`, `rt` — номера регистров).
Поле из `format` не обязано использоваться, но тогда будет предупреждение.

### Что должно быть в наборе (рекомендуется)

* `NOP`, `HLT` (`halt()`);
* загрузка константы, пересылка, чтение/запись памяти (в том числе в порты устройств — они же память!);
* арифметика/логика по выбранным `aluOps`;
* переход (безусловный) и хотя бы один условный (по `Z`, лучше ещё `C`/`N`);
* при включённом стеке — `CALL`, `RET`, `PUSH`, `POP`.
* Если набор опкодов слишком мал для задуманного — увеличьте `opcodeBits` (но следите за шириной слова).

## Контрольный список перед отправкой

1. `opcode` каждой инструкции помещается в `opcodeBits` и не повторяется.
2. `opcodeBits + ширины полей ≤ instrBits` для каждой инструкции (считайте!).
3. В `code` использованы только функции АЛУ и флаги, которые есть в `spec`.
4. `ramWords ≤ 2^ramAddrBits − число портов`.
5. В `accumulator` нет полей `rd/rs/rt` и нет `R[...]` — используется `A`.
6. Ответ — один валидный JSON без комментариев.
